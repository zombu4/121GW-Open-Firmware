# Changelog

What each release of the firmware and the emulator brought, newest first. The release page of a version shows only its own paragraphs.

New in v1.3.5 (F-1.35): current clamp mode (GitHub issue 39). A new SETUP page CLP in DCV, ACV, DCmV and ACmV (after dSP) takes the millivolts your clamp gives per ampere: off (default), 1, 10, 100 or 1000. With a setting the main display shows amperes: the same digits with the decimal point moved, the V sign replaced by A, and mA when the amperes would need more than four decimals; a current that does not fit the five digits shows OFL. The measurement, MIN/MAX, REL, HOLD, the bargraph and the sub display are not touched. The Bluetooth status frame carries the setting in byte 13 bits 7..5 (the voltage in the other bytes is unchanged, so older apps keep showing volts), the SD card log writes the main reading in A or mA, and the setting is a Bluetooth remote setting (id 0x020, bits 7..5). It is stored in bits 7..5 of EEPROM byte 0x020, which were unused; the other bits of the byte are never changed by it.

New in v1.3.4 (F-1.34): readings sized to the converter's real speed. Measured on a meter, the measuring chip takes two conversion times plus 0.79 ms for each result whenever its chopper is on (continuity, ohms, DC volts and millivolts, currents, diode, temperature), and the averages had been sized for one conversion time. They are now sized for the measured speed: the continuity display and its beep decision every 102 ms (was 250 ms), ohms every 105 to 154 ms (was 206 to 225 ms), currents and diode every 159 ms (was 212 ms), millivolts range 0 and temperature every 608 ms (was 811 ms), and after a DC volts range change from the lowest range a value 0.34 s sooner. DC volts, the highest ohm ranges and LowZ keep their timing; where a value now averages fewer results it is at most a quarter fewer, so readings stay steady. Calibration mode keeps every count, so a calibration is taken exactly as before. The emulator now converts at the measured speed too. Also in v1.3.4: a battery type setting for rechargeable NiMH cells (GitHub issue 36). The new SETUP page after the battery voltage shows `bAtAL` (alkaline, the default) or `bAtnH` (NiMH); REL or PEAK switches, a long SETUP saves. With NiMH the low-battery symbol, the logging stop and the Bluetooth low-battery flag come at 4.7 V instead of 4.1 V, before the weakest cell of the four is driven empty; settings can still be saved down to 4.1 V with either type. After switching on, the small display shows the version and then the battery voltage for the same 2 s (for example `4.95` with the V sign), in every function but VA; a key, a dial turn or a SETUP page ends it at once. A battery under the limit gives a double beep at switch-on (silent with the buzzer off).

New in v1.3.3 (F-1.33): continuity with a threshold and hysteresis of your own. The threshold page of the continuity function has two more choices, DNUSr (beep on a short, at or below your threshold) and UPUSr (beep on an open, at or above it: the one for intermittent connections, it sounds when the connection breaks). With either one the SETUP walk shows two more pages after bH: th, the threshold from 1 to 500 ohm in 1 ohm steps (30 ohm until you set it), and HY, the hysteresis from 0.1 to 25.0 ohm in 0.1 ohm steps (5.0 ohm until you set it): once the tone is on it stays on until the reading is that far past the threshold, so a reading near the threshold does not chatter. The 16 fixed thresholds work as before. The settings take three spare bytes of the meter's memory that share nothing with the calibration, the serial number or the other options; the 121GW Companion 1.3.1 shows and changes them.

Also in v1.3.3: a meter API over Bluetooth for scripts and test tools. The meter now takes its settings requests on every screen, not only while page Ld is shown, and two new requests: WHERE answers which dial position, function, SETUP page and edit state the meter shows, and SHOW moves the meter straight to any SETUP page, taking the same steps as SETUP presses, so every page behaves exactly as if reached with the keys. The logging interval (0 to 999 s) can now be set over Bluetooth too. Requests are refused while logging, in the MEM view, in calibration mode and while a page is being edited on the meter. The emulator's `tools/meter_api.py` runs them from the command line. Nothing in this touches the calibration, the serial number or the options.

New in v1.3.2 (F-1.32, experimental): one link for meters with the old BLE112 Bluetooth module, and packed downloads and updates for every meter (GitHub issue 30). When the 121GW Companion 1.3.0 asks for it, the meter sends everything in small blocks with repair bytes at a steady pace: its settings and serial only when they change (and every 2 s), each reading as a difference to the one before, the battery seldom, answers first in line. A damaged byte is repaired, a lost block costs only its own readings, never a wrong value, and the meter's full reading rate fits through the old module. This replaces the separate fixes of 1.2.9 and 1.3.0 (repair bytes per reading, the extra speeds), which are removed. Other apps and meters with the newer module are not affected. On link 2 the card list, downloads and settings travel in the same repaired blocks. Packed: the meter packs card files before sending them at the highest deflate setting, with Huffman codes built for each piece (log files to about 14 %), and takes updates packed on page Ld (with the bootloader 1.1.5 also in update mode; the firmware image to about two thirds); the unpacked bytes are checked exactly as before, and a damaged packed transfer stops with LdE10 and is sent again.

New in v1.3.0 (F-1.30, experimental): more readings a second for meters with the old BLE112 Bluetooth module (GitHub issue 30). The meter gets four extra speeds for the companion only, 5, 6, 7 and 8 readings a second (the bt setting keeps 2, 4, 10 and 20). The 121GW Companion 1.2.36 starts at 7, steps down when readings are lost, and remembers the speed each meter can do.

New in v1.2.9 (F-1.29, experimental): readings with repair data for meters with the old BLE112 Bluetooth module (GitHub issue 30). When the 121GW Companion (1.2.35) asks for it, the meter adds three repair bytes to every reading; the companion then corrects any single damaged byte of a reading, also in the digits that change, and drops a reading with two damaged bytes instead of showing a wrong value. Only the companion switches it on, only for the old module; other apps and meters with the newer module get the usual readings.

New in v1.2.8 (F-1.28, experimental): the meter sends to its Bluetooth module with two stop bits instead of one (GitHub issue 30). On meters with the old BLE112 module some bytes arrived shifted by one to three bits, always a byte that followed straight after another one; the second stop bit gives the module a short pause before every byte. Sending is about 9 % slower, which the link never needs; receiving is unchanged.

New in v1.2.7 (F-1.27): the service functions at power-on need two keys held together (GitHub issue 32). A single key pressed in the first 2 s after switching on or after a wake from auto power-off used to start one: a MODE pressed by chance showed CAL1. Now hold both keys while you turn the dial and keep them held for half a second, until the beep: MEM + PEAK opens the cal.bin backup / restore menu (then REL or PEAK, then MODE, as before), MODE + REL calibration mode, MODE + SETUP the date-code editing, RANGE + MIN/MAX all segments. MEM + HOLD stays the card update. Keys held at power-on do nothing else, and after a wake there is no service function. Nothing is written to the meter's memory by any of this.

New in v1.2.6 (F-1.26): a Bluetooth link that hangs is repaired by itself (GitHub issue 23). While the 121GW Companion (1.2.32) is connected it sends a one-byte "still here" every 5 s; when the meter hears nothing for 15 s it switches its Bluetooth module off for 5 s and on again, so a computer that kept the connection after the Companion let go (Windows was seen to) must release it, and the meter can be found again. A clean Disconnect switches this watch off first, and other Bluetooth apps for the meter never switch it on. The meter pages end with a new page bAcK (GitHub issue 31): SETUP there goes straight back to the measurement pages.

New in v1.2.5 (F-1.25): data over Bluetooth adjusts itself to the link (GitHub issue 30). Meters with the old BLE112 Bluetooth module carry about 150 bytes a second; the 121GW Companion 1.2.30 now sets the rate of the readings for the connection by itself (starting at 4 a second, down when readings arrive damaged, up again when the link stays clean, never above the saved bt setting, which is not changed), and reads the meter settings in small pieces that shrink until they arrive, as the card list and files already did. New key codes 0x99..0x9C (the reading rate for this power-on) and a paged settings request (start, max); everything before stays as it was.

New in v1.2.4 (F-1.24): the buzzer page has a third setting, qUiEt (GitHub issue 28): the keys are silent, but the meter still beeps for what it measures: the diode double beep and contact chirp, the diode short tone, the auto-hold capture, the limit test verdicts, the auto power-off warning and the power-off beep. b-On and b-OFF are unchanged; continuity and the safety warnings always sound. On the meter pages (on SEt hold SETUP), page 3: hold SETUP, REL or PEAK to b-On, b-OFF or qUiEt, hold SETUP to save. The companion offers it as "quiet (keys silent)" in the meter settings. The emulator's light theme is easier to read: a dimmer page, near-black text, the text one size larger.

New in v1.2.3 (F-1.23): the emulator has a light theme for its page: a Dark / Light / System switch in the Emulator box; the meter drawing and its display do not change (GitHub issue 26; the 121GW Companion 1.2.26 has one too). The manual now says that the buzzer page b-oFF silences the diode chirp as well (GitHub issue 27). The meter firmware is the same as v1.2.2 apart from its version number.

New in v1.2.2 (F-1.22): the SETUP pages come in two groups (GitHub issue 24). Pressing SETUP goes round the measurement pages only (REL view, display level, the function's own page, limit test, logging trigger and interval, MIN/MAX statistics) and ends on a new page SEt; hold SETUP on SEt for the meter pages (battery, auto power-off, buzzer, contrast, date and time, ID, backlight, Bluetooth, Ld-bt, card format, clock). Every page works as before. The manual now also says how to connect the 121GW Companion: do not pair the meter in the computer's Bluetooth settings (GitHub issue 23). With the bootloader 1.1.4 (release bl-v1.1.4) the meter switches Bluetooth on by itself after an update over Bluetooth, so the 121GW Companion reconnects and confirms the update without a key press (GitHub issue 23); the update that installs bootloader 1.1.4 still ends with Bluetooth off once. Verified working on a meter.

New in v1.2.1 (F-1.21): an optional diode contact chirp (idea and first version by @Cecilius, GitHub PR 22). The new SETUP page CHIrP (diode function only, after dSP; off by default) makes the diode beep report a contact: one double beep when a diode is connected, nothing while it stays connected, with open leads or a reversed diode, or when the probes are lifted. Off, the beep works as before. The 121GW Companion 1.2.23 shows and changes the setting. Verified working on a meter.

New in v1.2.0 (F-1.20): bargraph fixes (all three are in the original v2.05 too). In the DIODE 15 V range the bar no longer flashes full once per reading with open leads, and its label reads 50 (full bar 50 V) instead of 5 (GitHub issue 19). In the VA modes (uVA, mVA, VA) the bar's label now follows the range instead of keeping the one the function before left; where no label fits the range (full bar 5000 or 50000 of the unit shown) none is shown (GitHub issue 17). The emulator now also shows display states that last less than its 100 ms refresh, faint, as a short flash on the meter's glass. Verified working on a meter: the DIODE bar and its labels on both ranges.

New in v1.1.9 (F-1.19): careful mode for meters with the old Bluegiga BLE112 Bluetooth module (early v.01 boards), whose module damages single bytes on the link (GitHub issues 9 and 14): with the 121GW Companion 1.2.20 the meter sends every reading twice and answers card requests in small pieces, so readings, the card file list and downloads get through. The companion switches it on by itself; meters with the newer BGM220S module are not affected.

New in v1.1.8 (F-1.18): after the auto power-off ("-oFF-") a key press or a dial turn switches the meter on again, and Bluetooth comes back on if it was on. Until now the meter woke but then hung (a timer interrupt left pending while its clock was off), so only turning the dial to OFF and back on started it; the original v2.05 code has the same sequence. The auto power-off time is now selectable on the SETUP page APO: off, 1, 15, 30 (default) or 60 minutes (doubled while MIN/MAX is on); the 121GW Companion 1.2.19 shows and changes it. Verified working on a meter: the wake by a key, Bluetooth after the wake, and the 1-minute time with its warning beeps.

New in v1.1.7 (F-1.17): at power-on and at every wake the meter measures its RC run clock against its 4 MHz crystal, trims it in measured steps and gives the Bluetooth serial line (19200 baud to the Bluetooth module) the measured frequency, so the serial timing no longer carries the RC clock's error (data sheet: +-0.5 % from the factory, up to +-3 % with temperature). Reports of single damaged bytes on the Bluetooth link (GitHub issue 9) look like a timing mismatch on that line; whether this was the cause on those meters is not proven yet: the 121GW Companion 1.2.18 shows the meter's clock in its report (setting "Extended diagnosis"). If the measurement cannot be made, the meter works exactly as before. Also new: the 121GW Companion can take the meter off page Ld-bt (button "Leave Ld-bt"). Verified working on a meter: the clock measurement at power-on and after the dial was turned off and on (that meter's clock: -0.09 %), and leaving page Ld-bt.

New in v1.1.6: capacitance anti-hunting (CAP), off by default. With some ceramic capacitors of about 100 nF the capacitance range kept changing, the digits stayed blank and only the decimal point moved (EEVblog forum). The new SETUP page `HUnt` (CAP only, after `dSP`; `on` / `oFF` on the main display) makes the meter stay on the 1 µF range after the 100 nF range has found no result twice in a row, and show the value there; it lets go when another capacitor is connected, with open probes, on a range or function change, and at power-off. Not reproduced on a meter (no such capacitor at hand), so reports are welcome. The 121GW Companion (1.2.16) shows and changes the setting. The emulator can model such a capacitor (stimulus setting `cap_slow_ranges`; the physical cause is unproven). Version shown at power-on: F-1.16.

New in v1.1.5: an extended Bluetooth link diagnosis for the 121GW Companion (1.2.15). With "Extended diagnosis" switched on in the Companion's settings, the meter counts what happens on its Bluetooth module's serial line (bytes received, lost bytes, noise, framing errors, rejected commands) and the Companion shows the numbers in its report, so a slow or damaged link can be traced to the meter, the radio or the computer (GitHub issue 9). The counting is off unless the Companion switches it on and starts from zero at every power-on; nothing is stored. Fixed: according to the processor's reference manual, a byte lost on the module's serial line at the wrong moment (an overrun, also in v2.05, OF-71) could keep the meter's receive interrupt running for ever; it is now cleared (not seen on a meter).

Fixed in v1.1.4: the emulator on macOS can download the firmware builds again (it brought no list of trusted certificates, so every download from GitHub failed with "certificate verify failed"; the same fault as the 121GW Companion's update check, fixed in Companion 1.2.14). The firmware is the same as v1.1.3 apart from its version number.

New in v1.1.3 (experimental): capacitance in auto range waits a little longer on the 100 nF range (2.5 s instead of 2.0 s) before it moves to the 1 µF range, so capacitors near 100 nF keep the 100 nF range's resolution (0.01 nF). Tell us on GitHub or the EEVblog forum how it works with your capacitors.

Fixed in v1.1.2: SD card writes no longer stop part-way (GitHub issue 5): v2.05 ran every card access with the processor on the 4 MHz crystal and the PLL at 48 MHz, but the processor's reference manual (RM0038, 6.2) requires the PLL's VCO at 96 MHz for the SD interface (OF-69); card access now uses the 96 MHz VCO, and the processor runs at 32 MHz during card access (our choice). Formatting a 32 GB card takes 16 s instead of failing. The clock is also raised in steps the reference manual allows (OF-70). Battery runtime is slightly shorter while the card is in use (logging, card files over Bluetooth).

Fixed in v1.1.1: a card write that times out and is not confirmed by the card is written again (up to 3 attempts); the Bluetooth diagnosis tells which part of a write timed out, for how long, and what the card answered (the 121GW Companion 1.2.5 shows it). With v1.1.0 a 32 GB card still stopped a format on a meter.

Fixed in v1.1.0: a card that stays busy after a write longer than the meter waits (600 ms) no longer makes the write fail: the meter asks the card whether the block was written (ACMD22) and goes on.  On a meter a 32 GB card did this during a format, which then stopped and left the card without a file system (format it again with v1.1.0).

New in v1.0.9: the SD card can be formatted from the 121GW Companion (CARD view, "Format card", meter on the page Ld-bt, two-part bootloader): the same exFAT format as the SETUP page Fr, after the word FORMAT is typed.

Fixed in v1.0.8: SD cards above 4 GiB: the card size no longer wraps (a 32 GB card read as 1.72 GB, a v2.05 defect, OF-68); a card formatted on the meter (page Fr) with v1.0.4 to v1.0.7 got only that small volume: format it again to get the full card. Windows installers of the emulator and the companion ask for administrator rights and install into Program Files for all users; releases carry the user manual and the 121GW Companion.

Fixed in v1.0.7: resistance auto-range: a step up over several ranges (e.g. 1 kohm -> 100 kohm) no longer waits 1 s on the 50 Mohm range before it goes to the right range (0.5 s instead of 1.2 s in the emulator; open -> 10 ohm 0.2 s and 10 ohm -> 40 Mohm 0.4 s, against 1.5 s and 1.6 s in v2.05); the digits blank at a resistance range change instead of briefly showing the new decimal point on the old digits (".0FL", "01.00"). The resistance timings are emulator measurements, not yet measured on a meter. New user manual (firmware/docs/manual/manual.pdf).

Fixed in v1.0.6: restoring cal.bin (MEM at power-on, PEAK, MODE) works again: v1.0.4 and v1.0.5 refused every file ("-Err-", nothing written); a cal.bin is now restored only to the meter whose serial number it holds (another meter's file or one written by the emulator is refused, nothing written); holding MEM a little longer while switching on no longer starts logging instead of the backup / restore (a v2.05 defect, OF-67).

Fixed in v1.0.5: the DCV reading no longer freezes on a steadily changing voltage (GitHub issue 3: the step detection of the fast averaging took a ramp for a step); SD sectors read into or written from an unaligned buffer were shifted by the DMA (a v2.05 driver defect, OF-66).
